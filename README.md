# Reasoning Bench

A small, reproducible benchmark that measures **specific reasoning abilities** of LLMs under controlled conditions, and checks whether those abilities survive harmless changes to the question.

> This benchmark does not measure "general reasoning" or general intelligence. It measures the listed abilities, on the listed tasks, under the listed conditions.

## Core idea

1. Every question is generated by code, so the answer is verified by code, not opinion.
2. Every flawed question has a **repaired twin**: the same scenario with the flaw fixed. This catches models that flag everything.
3. Every question has three versions: **original**, **surface-perturbed** (renamed, reordered, reworded), and **distractor-added** (irrelevant details).
4. Each model is run 5 times per question. We report mean and variance.
5. The headline metric is the **robustness gap**: accuracy on original minus accuracy on perturbed.
6. A private held-out set (never published) guards against contamination.

## Assumption detection: two tiers

The first track asks: does the model notice a hidden, false, or missing premise, or does it answer as if everything were fine?

**Tier 1: controlled puzzles.** Ages, schedules and number constraints. Small and clean, used as the baseline.

**Tier 2: realistic business scenarios.** The same flaw types, written as documents a business would actually use:

| Domain | Example flaw |
|---|---|
| HR operations | A hiring plan needs more hires than the approved budget covers |
| HR operations | A leave question assumes an entitlement the policy does not give |
| Finance | A stated loan instalment does not match the loan terms |
| Finance | A loan total is requested but no interest rate is given |
| Project planning | Two concurrent tasks need more engineers than the team has |
| Project planning | Tasks are assumed to run in parallel, but one depends on the other |
| Compliance | Two policy clauses overlap and conflict |
| Compliance | A deletion date is requested for an account that is still open |
| Compliance | A training deadline is requested but the start date is missing |

Scope note: Tier 2 tests whether a model catches inconsistencies in business documents and plans. It does not involve judging candidates or people.

## Reproduce

The generators use only the Python standard library (3.8+), so there is nothing to install.

```
python generators/assumption_detection.py
python generators/assumption_detection_domain.py
```

Both are deterministic: the same seed always produces the same questions. The private held-out set is regenerated locally from the seed and is never uploaded.

The model runner comes next:

```
python runner/run.py --track assumption_detection --models config/models.yaml --runs 5
python runner/report.py
```

## Limitations

- Small question counts per track; confidence intervals are reported and are wide.
- Generated questions are cleaner than real-world problems. Tier 2 scenarios are templates, so wording variety is limited and real company documents are messier.
- Public questions can leak into future training data; the private set reduces but does not remove this.
- Scores depend on the prompt format; the exact prompts are logged.
- Answer keys are verified by code, but a human should still read a sample of questions for fairness and realism.
